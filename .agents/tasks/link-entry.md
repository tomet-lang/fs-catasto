# Work order: `link` entries (catasto declares and places a symlink)

Ordered 2026-10-25. Self-contained: you do not need the conversation that produced it. Read `AGENTS.md` and `CONTRIBUTING.md` first; they bind
you (nix dev shell, `just` recipes, `.tmt` is the source of every `.md`, English only, `jj --no-pager`, no push, do not touch changes you did not make).

Builds on `feat: follow or keep symlinks in git sources`, which can place an *upstream* symlink (`source: { …, symlink: keep }`). This order adds the
other half: a symlink that the **manifest itself declares**, with no upstream behind it.

## 1. Why

```
"CLAUDE.md": { link: "AGENTS.md" }
```

says: in this workspace, `CLAUDE.md` is a symlink to `AGENTS.md`. Today the only way to get that is to `ln -s` by hand and hope nobody replaces it with a
copy. catasto should declare it, place it, lock it and notice drift, like any other managed path.

## 2. Decisions (taken by the orderer; do not reopen)

1. **Syntax.** An entry is `{ source: … }` **or** `{ link: "text" }`, never both and never neither. `link` takes a string.
2. **The text is the link text, verbatim, relative to the directory the link is placed in** -- exactly what `ln -s TEXT DEST` would take. There is no
   workspace-root-relative spelling (no `file:` prefix) in this order. `"docs/x/CLAUDE.md": { link: "../../AGENTS.md" }` is what it looks like.
3. **A target that does not exist is not a violation.** The target may be generated later (in this repository `AGENTS.md` is generated by `sisho fix`).
   Whether `check` warns is the job of `check-dangling-link-warning.md`; this order emits no warning.
4. The text is checked when the manifest loads (section 3.1), but catasto never decides what the target *should* be.

## 3. Behaviour to build

### 3.1 Manifest

- `Entry` in `crates/catasto-core/src/manifest.rs` (today `{ source }` with `deny_unknown_fields`) accepts `link` as the alternative to `source`. Both
  present, or neither, or a `link` that is not a string: a load error whose message shows the two valid shapes.
- Model it as a new `Source::Link(String)` (the text), so equality, lock comparison, `unlocked` detection and the placing code are shared. `link:` is an
  entry-level spelling only: `source: { link: "x" }` stays a load error in the manifest. (The lock needs `Source::Link` to round-trip; keep the two
  readers separate if that is what it takes.)
- Load-time checks on the text, each a clear error naming the entry: empty; contains NUL; absolute (starts with `/`); resolved lexically from the
  directory of the destination, it climbs out of the workspace (`..` past the root).
- A `link` entry works with `::upstreams` present or absent; upstream resolution leaves it alone.

### 3.2 Lock

- `catasto.lock` records `"source": { "link": "AGENTS.md" }` and `"sha256"` = sha256 of the link text bytes (as `sha256_link` of the placed link
  would give). No `commit`. Entries without `link` are byte-for-byte unchanged; `version` stays 1.
- `catasto lock` has nothing on disk to adopt for a link entry: it computes the digest from the manifest and does **not** require the destination to
  exist (`check` will say `missing`/`modified`). Other entries behave as today.

### 3.3 Sync

- No fetching and no git cache for link entries. `sync` places the link with the same code that places a kept upstream link (create parents, replace
  whatever is at the destination atomically, never write through a symlink, unix only; a clear error elsewhere). `sync --only` works for them.
- A destination that is a directory is an error naming the path, not a partial result. The "every source is read before anything is written" rule holds.

### 3.4 Check

Same rows as a kept upstream link (`check.rs`):

| destination | result |
|---|---|
| absent | `Missing` |
| not a symlink (regular file, directory) | `Modified` |
| symlink whose `read_link` digest differs from the lock | `Modified` |
| symlink with the locked text | clean, whether or not the target exists |
| declared, lock has no entry or another source | `Unlocked` |

`Stale` and `local_path` are for local-path sources only; a link entry is neither.

### 3.5 `list`, `add`, `remove`

- `catasto list` (and `--json`): show a link entry as `link -> AGENTS.md`; the JSON carries a field for it (shape yours, say which).
- `catasto add DEST --link TEXT` declares, places and locks a link entry. `--link` is one more member of the exclusive `kind` group of `AddArgs`
  (`app/src/cli.rs`), so the positional `from` becomes optional and is required exactly for the other three kinds; `--link` with `--rev` is an error.
  A failed `add` still leaves nothing behind. `SourceText` in `edit.rs` gets a `Link` shape and `entry_text` writes `"DEST": {\n  link: "TEXT"\n}` in
  the layout the other entries use.
- `catasto remove DEST` works unchanged for a link entry. `--delete-file` removes the link itself and must never touch what it points at; test it with a
  target that must survive.
- `catasto upstream remove` must not be confused by a link entry (it scans entries for `upstream`; prove it with a test).

## 4. Tests (all required; symlink tests are `#[cfg(unix)]`)

- manifest: `link` parses; `source` + `link`, neither, a non-string, empty, NUL, absolute, climbing out all fail with the right message; `source: { link }`
  is rejected; a link entry next to `::upstreams` entries.
- lock: round trip; the digest equals `sha256_link` of the placed link; a lock with no link entry is unchanged byte for byte; changing the text makes
  the entry `unlocked`, `sync` fixes it.
- sync: places the link (text exact); replaces an existing regular file, an existing other link, and (the dangerous one) does not write through; a
  directory at the destination is an error; parents are created; `--only`.
- check: every row of the table, including a dangling target (clean) and a link loop in the workspace (clean).
- `lock` on a link entry with no destination on disk.
- add / remove / list / `upstream remove`, as in 3.5, plus one `app/tests` end-to-end run.

Never edit a generated `.md`. Leave `tmtroot/spec/**`, `tmtroot/dev/idea.tmt` and `tmtroot/generated/config.tmt` alone.

## 6. Acceptance

`just build`, `just test`, `just clippy` (`-D warnings`), `just docs-check` pass in the nix shell; existing tests unchanged and green; a manifest and
lock from before this change behave exactly as before. Manual proof for the hand-back, in a throwaway directory: `add CLAUDE.md --link AGENTS.md`,
`check` clean with no `AGENTS.md` present, replace the link with a copy -> `modified`, `sync` -> link again, edit the text in the manifest ->
`unlocked`, `sync`, `remove --delete-file` leaves `AGENTS.md` alone.

## 7. Out of scope

A workspace-root-relative spelling. Warnings about dangling links (`check-dangling-link-warning.md`). Links to directories being treated specially
(allowed, nothing more). Windows (compiles, clear error). Local-path or git sources producing links (that is `symlink: keep`, already done).
